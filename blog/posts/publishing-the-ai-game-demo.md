I published a free demo of my AI-driven RPG on itch.io. The game is called Echoloom. This post covers what I cut to get it out, how I tested it without an LLM, what my five playtesters said, and what is still broken.

## What the demo is

Echoloom is a 2D RPG built in Godot 4.7. Its maps, quests, NPCs, and items are generated by an LLM, returned as structured data, and then run by the game engine. The demo is three levels long, does not have a save system, and keeps state in memory. At the end it shows the unfinished quests and says the demo ends there.

The demo needs an API key to generate content. I did not build a fallback mode, so without a key the game can't create new content.

## What I cut to ship it

The full version has a server-side save system, with the server acting as the authority on game state. That was too much for a first release, so I removed it from the demo. I also started a new repository with only the files the demo needs, which kept unused code out of the public version.

The main lesson was to decide what the demo must prove. For me, that was that an LLM can generate playable game content and the engine can run it. Enemy generation, dynamic sprites, and cross-level quests were all left out.

## Testing without an LLM

Calling a live model for every test is slow and expensive, and its output changes each time. So I split testing into three layers:

1. **Logic tests** in pytest, covering the quest, item, and state rules. Sixteen pass.
2. **A scripted test server** that replays fixed scenarios. The scenarios cover a quest with items to collect and hand over, and a reward at the end.
3. **Recorded AI responses**, which I planned as the third layer and have not finished.

The scripted scenarios caught more real bugs than I expected, mainly in how items were handed over and how quests were queued.

## What playtesters said

Five friends played the demo. Before they started, I told them which features were not built yet. Their feedback was that it felt like a new experience compared with the games they usually play. I did not collect structured feedback, so I can't say what they liked most or what confused them.

Next time I'll ask a few specific questions: what was confusing, what they'd change, and whether they'd play again.

## What's still open

- **Dialog bug:** Choosing to accept a quest shows the in-progress text instead of the offer text.
- **End card and level cap:** Both are unfinished.
- **Download size:** The itch download is about 350 MB. That is too large for most people to try, and I plan to reduce it.

## What's next

I'm fixing the dialog bug first, then the download size, then recording a gameplay video. The video will be linked here once it is published.

Publishing a rough demo was worth it. Real players found things my own testing missed, and I learned more from the release than from any amount of solo testing.
